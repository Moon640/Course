## 1. 시간 복잡도의 정의와 필요성

시간 복잡도(Time Complexity)는 입력 데이터의 크기가 증가할 때 알고리즘의 실행 시간이 어떤 비율로 증가하는지를 나타내는 개념이다. 실제 실행 시간을 초 단위로 직접 측정하는 것과는 다르다. 실행 시간은 컴퓨터의 성능, 운영체제, Java 실행 환경 등에 따라 달라질 수 있기 때문에, 시간 복잡도에서는 입력 크기에 따른 핵심 연산의 실행 횟수를 중심으로 분석한다.

예를 들어 입력값이 `n`개이고 모든 입력값을 한 번씩 확인한다면 핵심 연산은 약 `n`번 실행된다. 입력값마다 다시 전체 입력값을 확인한다면 핵심 연산은 약 `n × n`, 즉 `n²`번 실행된다.

시간 복잡도 분석이 필요한 이유는 다음과 같다.

- 입력 크기가 커졌을 때 프로그램의 성능을 예측할 수 있다.
- 같은 결과를 만드는 여러 알고리즘의 효율성을 비교할 수 있다.
- 반복문이나 중첩 반복문에서 발생하는 병목 현상을 찾을 수 있다.
- 실행 시간이 지나치게 증가하기 전에 개선 방법을 설계할 수 있다.
- 특정 컴퓨터의 성능과 관계없이 알고리즘 자체의 효율성을 평가할 수 있다.

## 2. Big O 표기법의 개념과 상황별 예시

Big O 표기법은 입력 크기가 충분히 커졌을 때 알고리즘의 실행 시간이 증가하는 정도를 표현한다. 시간 복잡도를 계산할 때는 영향력이 가장 큰 항만 남기고, 상수와 낮은 차수의 항은 생략한다.

예를 들어 연산 횟수가 `3n² + 2n + 5`라면 입력값이 커질수록 `n²`의 영향이 가장 커지므로 `O(n²)`으로 표현한다. 반복문이 연속으로 세 번 실행되어 총 `3n`번의 연산이 발생하더라도 상수 3은 생략하므로 `O(n)`이다.

| Big O | 의미 | 상황 예시 |
|---|---|---|
| `O(1)` | 입력 크기와 관계없이 일정한 시간이 걸림 | 배열의 특정 위치 값 확인, 스택의 `push()`와 `pop()` |
| `O(log n)` | 입력이 커져도 연산 횟수가 완만하게 증가함 | 정렬된 데이터의 이진 탐색 |
| `O(n)` | 입력 크기에 비례하여 실행 시간이 증가함 | 배열 또는 리스트 전체 순회 |
| `O(n log n)` | 선형 순회와 로그 연산이 결합됨 | 효율적인 비교 정렬 |
| `O(n²)` | 입력 크기의 제곱에 비례하여 증가함 | 이중 반복문, 각 원소마다 전체 데이터 순회 |

이 보고서에서는 다음 기호를 사용한다.

- `n`: 문제 01에 입력된 파동수의 개수
- `m`: 문제 01의 명령행 인수 전체 문자 수
- `L`: 문제 02에 입력된 문장의 전체 문자 수
- `k`: 문제 02의 명령행 인수 개수

## 3. 문제 01 코드의 시간 복잡도 분석

### 3.1 코드의 처리 과정

`RoadToBiodome01.java`는 다음 순서로 동작한다.

1. 명령행 인수로 전달된 문자열을 정리하고 숫자로 변환한다.
2. 숫자가 0에서 1000 사이인지 검사한다.
3. 올바른 숫자를 `ArrayList`에 저장한다.
4. 리스트의 각 숫자에 대해 `countOccurrences()`를 호출한다.
5. 리스트 전체를 순회하여 해당 숫자의 등장 횟수를 계산한다.
6. 한 번만 등장하는 첫 번째 숫자를 출력한다.

### 3.2 입력 처리의 시간 복잡도

문자열의 대괄호와 쉼표를 제거하고, 공백을 기준으로 나눈 뒤, 각 값을 정수로 변환한다. 모든 입력 문자를 처리하는 데 걸리는 시간은 전체 입력 문자 수에 비례하므로 `O(m)`이다. 숫자 `n`개를 리스트에 추가하는 과정은 평균적으로 `O(n)`이다.

### 3.3 `countOccurrences()`의 시간 복잡도

```java
public static int countOccurrences(List<Integer> waveNumbers, int target) {
    int count = 0;

    for (int waveNumber : waveNumbers) {
        if (waveNumber == target) {
            count++;
        }
    }

    return count;
}
```

이 메서드는 특정 숫자의 등장 횟수를 세기 위해 리스트의 처음부터 끝까지 확인한다. 리스트에 숫자가 `n`개 있다면 비교 연산이 `n`번 실행되므로 시간 복잡도는 `O(n)`이다.

### 3.4 반복되지 않는 숫자를 찾는 부분

```java
for (int waveNumber : waveNumbers) {
    if (countOccurrences(waveNumbers, waveNumber) == 1) {
        System.out.println(waveNumber);
        return;
    }
}
```

바깥쪽 반복문은 최악의 경우 숫자 `n`개를 모두 확인한다. 각 반복마다 `O(n)`인 `countOccurrences()`가 실행된다.

```text
n번 반복 × 매번 n번 비교 = n²번 비교
```

따라서 이 부분의 최악 시간 복잡도는 `O(n²)`이다. 한 번만 등장하는 숫자가 리스트의 첫 번째 위치에 있다면 `countOccurrences()`가 한 번만 실행되므로 최선 시간 복잡도는 `O(n)`이다. 그러나 Big O는 일반적으로 입력이 가장 불리하게 주어지는 최악의 경우를 기준으로 표현하므로 문제 01의 전체 시간 복잡도는 `O(m + n²)`, 숫자 개수를 중심으로 단순화하면 `O(n²)`이다.

### 3.5 문제 01의 공간 복잡도

입력된 숫자 `n`개를 `ArrayList`에 저장하므로 `O(n)`의 추가 공간이 필요하다. 문자열을 정리하고 나누는 과정에서도 입력 크기에 비례하는 임시 문자열과 배열이 생성될 수 있다. 따라서 전체 공간 복잡도는 `O(m + n)`이며, 숫자 개수를 중심으로 보면 `O(n)`이다.

### 3.6 문제 01 분석 요약

| 처리 부분 | 시간 복잡도 |
|---|---:|
| 명령행 인수 문자열 처리 | `O(m)` |
| 숫자 `n`개 리스트 저장 | 평균 `O(n)` |
| `countOccurrences()` 1회 호출 | `O(n)` |
| 한 번만 등장하는 숫자 탐색 | 최선 `O(n)`, 최악 `O(n²)` |
| 전체 코드 | 최악 `O(m + n²)`, 단순화하면 `O(n²)` |

## 4. 문제 02 코드의 시간 복잡도 분석

### 4.1 코드의 처리 과정

`RoadToBiodome02.java`는 다음 순서로 동작한다.

1. 명령행 인수가 입력되었는지 확인한다.
2. 여러 명령행 인수를 하나의 문장으로 합친다.
3. 문장의 길이와 공백 입력 여부를 검사한다.
4. 문자의 개수만큼 `char` 배열 스택을 생성한다.
5. 문장의 모든 문자를 스택에 `push()`한다.
6. 스택이 빌 때까지 문자를 `pop()`하여 역순 배열에 저장한다.
7. 역순 문자열을 출력한다.

### 4.2 기본 스택 연산

```java
public static void push(char value) {
    stack[++top] = value;
}

public static char pop() {
    if (isEmpty()) {
        throw new IllegalStateException("스택이 비어 있습니다.");
    }

    return stack[top--];
}

public static boolean isEmpty() {
    return top == -1;
}
```

`push()`는 `top`을 한 칸 증가시킨 뒤 배열의 해당 위치에 문자를 저장한다. `pop()`은 배열의 `top` 위치에 있는 문자를 반환한 뒤 `top`을 한 칸 감소시킨다. `isEmpty()`는 `top`이 `-1`인지 확인한다. 세 연산 모두 입력 크기와 관계없이 일정한 수의 연산만 수행하므로 각각 `O(1)`이다. `peek()`도 배열의 `top` 위치만 확인하므로 `O(1)`이다.

### 4.3 명령행 인수 결합

`combineArguments()`에서는 먼저 모든 명령행 인수의 길이를 확인한다. 그다음 각 문자를 `char[]` 배열에 복사한다. 문장의 전체 길이가 `L`일 때 길이 계산은 `O(k)`, 모든 문자 복사는 `O(L)`이다. 일반적으로 `L`이 `k` 이상이므로 전체 시간 복잡도는 `O(L)`로 표현할 수 있다.

### 4.4 공백 입력 검사

```java
message.trim().isEmpty()
```

`trim()`은 문자열의 앞뒤 공백을 확인하고 필요한 경우 새로운 문자열을 만든다. 최악의 경우 문장의 모든 문자를 확인하므로 `O(L)`이다.

### 4.5 모든 문자 `push()`

```java
for (int i = 0; i < message.length(); i++) {
    push(message.charAt(i));
}
```

`push()` 한 번은 `O(1)`이고, 문자가 `L`개이므로 총 `L`번 실행된다.

```text
L번 반복 × O(1) = O(L)
```

### 4.6 모든 문자 `pop()`

```java
while (!isEmpty()) {
    reversedCharacters[index++] = pop();
}
```

`isEmpty()`와 `pop()`은 각각 `O(1)`이고, 문자가 모두 제거될 때까지 `L`번 반복한다. 따라서 이 부분의 시간 복잡도도 `O(L)`이다.

### 4.7 문제 02의 전체 시간 복잡도

문제 02는 입력 결합, 공백 검사, `push()`, `pop()`, 결과 문자열 생성 과정에서 문장을 여러 번 순회한다.

```text
O(L) + O(L) + O(L) + O(L) + O(L) = O(5L) = O(L)
```

Big O 표기법에서는 상수를 제거하므로 전체 시간 복잡도는 `O(L)`이다. 문장을 거꾸로 출력하려면 최소한 모든 문자를 한 번씩 확인해야 하므로 `O(L)`은 이 문제에서 적절하고 효율적인 시간 복잡도이다.

### 4.8 문제 02의 공간 복잡도

원문을 결합하기 위한 `char[]`, 직접 구현한 스택 배열, 역순 결과 배열이 각각 문장 길이에 비례하는 공간을 사용한다. 여러 개의 `O(L)` 공간을 사용하더라도 상수는 생략하므로 전체 공간 복잡도는 `O(L)`이다.

### 4.9 문제 02 분석 요약

| 처리 부분 | 시간 복잡도 |
|---|---:|
| `push()` 1회 | `O(1)` |
| `pop()` 1회 | `O(1)` |
| `peek()` 1회 | `O(1)` |
| `isEmpty()` 1회 | `O(1)` |
| 명령행 인수 결합 | `O(L)` |
| 공백 입력 검사 | `O(L)` |
| 모든 문자 `push()` | `O(L)` |
| 모든 문자 `pop()` | `O(L)` |
| 전체 코드 | `O(L)` |

## 5. 병목 현상 분석

### 5.1 문제 01의 병목 현상

문제 01의 가장 큰 병목은 리스트의 각 숫자마다 `countOccurrences()`를 호출하는 부분이다. 동일한 숫자가 여러 번 들어 있어도 그 숫자의 등장 횟수를 매번 처음부터 다시 계산한다.

예를 들어 리스트에 숫자가 100,000개 있고 한 번만 등장하는 숫자가 마지막에 있다면, 리스트 전체를 최대 100,000번 다시 확인하게 된다. 단순 계산으로 최대 약 `100,000 × 100,000`번의 비교가 발생할 수 있다. 입력 크기가 두 배가 되면 비교 횟수는 약 네 배로 증가하기 때문에 큰 입력에서 성능이 급격히 낮아진다.

병목의 원인은 각 숫자의 등장 횟수를 저장하지 않고 필요할 때마다 전체 리스트를 다시 순회하는 데 있다.

### 5.2 문제 02의 병목 현상

문제 02의 전체 시간 복잡도는 `O(L)`이므로 입력 크기가 증가해도 실행 시간은 선형적으로 증가한다. 점근적인 관점에서 심각한 병목은 없다.

다만 최대 1,000,000자의 입력을 처리할 때는 다음 과정에서 문장 전체를 여러 번 순회하거나 추가 배열을 생성한다.

- 명령행 인수 길이 계산
- 인수를 하나의 문자열로 결합
- `trim()`을 이용한 공백 검사
- 스택에 모든 문자 저장
- 스택에서 모든 문자 제거
- 결과 문자열 생성

이 과정들은 모두 `O(L)`이므로 Big O는 변하지 않지만, 실제 실행 시간과 메모리 사용량을 증가시키는 상수 요인이 될 수 있다.

## 6. 최적화 방안

### 6.1 문제 01: 빈도 배열을 이용한 `O(n)` 최적화

문제 01에서는 파동수의 범위가 0에서 1000으로 제한되어 있다. 따라서 크기가 1001인 정수 배열을 만들고, 각 파동수를 배열의 인덱스로 사용하여 등장 횟수를 저장할 수 있다.

```java
int[] frequencies = new int[1001];

for (int waveNumber : waveNumbers) {
    frequencies[waveNumber]++;
}

for (int waveNumber : waveNumbers) {
    if (frequencies[waveNumber] == 1) {
        System.out.println(waveNumber);
        return;
    }
}
```

첫 번째 반복문은 숫자별 등장 횟수를 한 번씩 기록하므로 `O(n)`이다. 두 번째 반복문은 입력 순서를 유지하면서 등장 횟수가 1인 첫 번째 숫자를 찾으므로 `O(n)`이다.

```text
O(n) + O(n) = O(2n) = O(n)
```

따라서 기존 `O(n²)`을 `O(n)`으로 줄일 수 있다. 추가로 사용하는 빈도 배열의 크기는 항상 1001로 고정되어 있다. 입력 크기 `n`과 관계없이 고정된 공간을 사용하므로 입력 크기를 기준으로는 `O(1)`의 추가 공간이다. 이 방식은 `HashMap`과 `HashSet`을 사용하지 않으므로 문제 01의 제약사항도 충족한다.

### 6.2 문제 01: 정렬을 이용한 대안

값의 범위가 제한되어 있지 않다면 입력값을 복사하여 정렬한 뒤 인접한 값들을 비교하는 방법을 사용할 수 있다. 일반적인 효율적 정렬의 시간 복잡도는 `O(n log n)`이므로 기존의 `O(n²)`보다 개선된다. 그러나 현재 문제에서는 값의 범위가 0에서 1000으로 고정되어 있으므로 빈도 배열을 사용하는 `O(n)` 방식이 더 적합하다.

### 6.3 문제 02: 전체 순회 횟수와 임시 객체 줄이기

문제 02는 이미 `O(L)`이므로 점근적인 시간 복잡도를 더 낮추기는 어렵다. 대신 다음과 같이 실제 연산 횟수와 메모리 사용량을 줄일 수 있다.

1. 명령행 인수를 결합할 때 공백이 아닌 문자가 있는지도 함께 확인한다.
2. 별도의 `trim()` 호출을 제거한다.
3. 원문 문자열을 만든 후 다시 스택에 복사하지 않고, 명령행 인수의 문자를 스택에 직접 `push()`한다.
4. 결과를 저장하는 `char[]`은 유지하여 `StringBuilder` 없이 출력 문자열을 생성한다.

공백 여부를 `push()` 과정에서 함께 검사하는 예시는 다음과 같다.

```java
boolean hasNonWhitespace = false;

for (int i = 0; i < message.length(); i++) {
    char current = message.charAt(i);
    push(current);

    if (!Character.isWhitespace(current)) {
        hasNonWhitespace = true;
    }
}

if (!hasNonWhitespace) {
    System.out.println("입력된 메시지가 올바르지 않습니다. 다시 한번 확인해주세요.");
    return;
}
```

이 최적화를 적용해도 모든 문자를 한 번 이상 확인해야 하므로 시간 복잡도는 여전히 `O(L)`이다. 그러나 별도의 `trim()` 순회와 임시 문자열 생성을 피할 수 있어 실제 실행 비용을 줄일 수 있다.

### 6.4 최적화 전후 비교

| 문제 | 기존 시간 복잡도 | 최적화 후 시간 복잡도 | 핵심 개선점 |
|---|---:|---:|---|
| 문제 01 | 최악 `O(n²)` | `O(n)` | 크기 1001의 빈도 배열에 등장 횟수를 한 번만 기록 |
| 문제 02 | `O(L)` | `O(L)` | 불필요한 전체 순회와 임시 객체를 줄여 상수 비용 개선 |

---

## 7. 결론

문제 01은 각 숫자마다 리스트 전체를 다시 확인하기 때문에 최악의 경우 `O(n²)`의 시간이 필요하다. 입력값의 범위가 0에서 1000으로 제한된다는 조건을 활용해 빈도 배열을 사용하면 각 숫자의 등장 횟수를 한 번만 계산할 수 있으며, 전체 시간 복잡도를 `O(n)`으로 줄일 수 있다.

문제 02의 `push()`, `pop()`, `peek()`, `isEmpty()`는 모두 `O(1)`이고, 문자의 입력과 출력 과정은 문장 길이에 비례하므로 전체 시간 복잡도는 `O(L)`이다. 문장을 역순으로 출력하려면 모든 문자를 확인해야 하므로 점근적으로 적절한 시간 복잡도이다. 다만 공백 검사와 문자 복사를 다른 반복 과정과 결합하면 Big O는 그대로 유지하면서 실제 연산 횟수와 메모리 사용량을 줄일 수 있다.

이번 분석을 통해 시간 복잡도는 반복문의 개수만 보는 것이 아니라, 반복문 안에서 호출되는 메서드가 다시 얼마나 많은 데이터를 순회하는지까지 함께 확인해야 정확하게 계산할 수 있다는 점을 알 수 있었다.
